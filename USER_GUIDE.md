# Руководство пользователя плагином Redmine Hierarchy Sort

Данное руководство подробно описывает, как использовать все возможности плагина для эффективного управления иерархическими списками задач в Redmine.

## 1. Включение иерархического режима

1. Перейдите в раздел **Задачи** нужного проекта или в глобальный раздел **Задачи**.
2. Нажмите **Новый запрос** или выберите существующий и нажмите **Редактировать**.
3. В блоке **Опции** (внизу формы) найдите и отметьте чекбокс **Дерево подзадач**.
4. После активации этого чекбокса форма автоматически расширится, и появятся два новых блока:
   - **Фильтры подзадач**
   - **Сортировка подзадач**

> **Совет:** Чекбокс **Показывать связи** также находится в блоке "Опции". Его включение добавит иконку 🔗 к задачам, имеющим связи.

## 2. Настройка фильтрации

Плагин разделяет фильтрацию на два независимых уровня:

### 2.1. Фильтры корневых задач
Используйте стандартный блок **Фильтры** в верхней части формы. Эти условия применяются только для отбора корневых задач. 
- *Важно:* Если корневая задача не проходит фильтр, всё её поддерево (все вложенные задачи) будет скрыто, независимо от их собственных параметров.

### 2.2. Фильтры подзадач
Используйте блок **Фильтры подзадач**. Эти условия применяются рекурсивно ко всем задачам внутри дерева, начиная с первого уровня вложенности.
- Если подзадача не проходит этот фильтр, она и все её собственные потомки будут скрыты.
- Если фильтр не задан, отображаются все потомки найденных корневых задач.

### 2.3. Фильтрация по полям родительской задачи (Новая возможность)
В стандартном блоке **Фильтры** появилась отдельная группа полей с названием **Родительская задача**. 
- Вы можете добавить условие, например: `Верх.: Статус` = `Открыт`.
- Это позволит показать только те задачи, чей непосредственный родитель находится в работе, даже если сама текущая задача закрыта.
- Поддерживаются все стандартные поля (Статус, Приоритет, Автор, Исполнитель, Пользовательские поля и т.д.).

## 3. Настройка сортировки

Сортировка также разделена на два уровня:

### 3.1. Сортировка корневых задач
Используйте стандартный блок **Сортировать**. Он определяет порядок только корневых задач на странице.

### 3.2. Сортировка подзадач
Используйте блок **Сортировка подзадач**. 
- Эта сортировка применяется **только к задачам одного уровня** (между собой, как "братья").
- Вложенные уровни всегда следуют за своим родителем и сортируются внутри своей ветки согласно этим же критериям.
- Если сортировка не задана, используется порядок по умолчанию (обычно по ID или дате создания).

### 3.3. Сортировка по полям родительской задачи (Новая возможность)
В выпадающем списке блока **Сортировать** теперь доступны поля с префиксом `Верх.: ` (например, `Верх.: Приоритет`, `Верх.: Пользовательское поле 5`).
- Это позволяет упорядочить задачи внутри группы, основываясь на характеристиках их непосредственного родителя.
- *Пример:* Сортировка "Верх.: Приоритет (по убыванию)" сгруппирует задачи так, что сначала пойдут задачи, чьи родители имеют наивысший приоритет.

## 4. Работа с визуализацией связей

1. Включите опцию **Показывать связи** в блоке "Опции".
2. В списке задач у строк, имеющих связи, появится иконка 🔗.
3. **Просмотр:** Наведите курсор на иконку, чтобы увидеть всплывающую подсказку "Связи".
4. **Детализация:** Кликните на иконку. Откроется всплывающее окно (popover), где связи сгруппированы по типам:
   - `→` Исходящая связь (текущая задача влияет на другую).
   - `←` Входящая связь (другая задача влияет на текущую).
   - `↔` Двунаправленная связь (например, "Связана с").
5. Клик по номеру задачи в этом окне осуществит переход к ней.

## 5. Практические сценарии использования

### Сценарий А: "Активные проекты с историей подзадач"
**Цель:** Видеть только открытые корневые задачи, но при этом отображать все их подзадачи (включая закрытые), отсортированные по дате.
**Настройка:**
- Фильтры: `Статус` = `Открыт`
- Сортировка: `Приоритет` (по убыванию)
- ✅ `Дерево подзадач`
- Фильтры подзадач: *оставить пустыми*
- Сортировка подзадач: `Дата создания` (по возрастанию)

### Сценарий Б: "Поиск задач, заблокированных открытыми родителями"
**Цель:** Найти задачи, которые сами по себе могут быть закрыты, но их родитель всё ещё открыт и блокирует работу.
**Настройка:**
- Фильтры: `Верх.: Статус` = `Открыт` И `Верх.: Трекер` = `Блокирующая задача`
- ✅ `Дерево подзадач`
- ✅ `Показывать связи`

## 6. Часто задаваемые вопросы (FAQ)

**В: Как работает пагинация в иерархическом режиме?**
О: Пагинация применяется исключительно к корневым задачам. Если лимит страницы равен 25, вы увидите 25 корневых веток. Каждая ветка будет отображена целиком со всеми своими прошедшими фильтрацию потомками, даже если это превысит 25 строк на странице.

**В: Что произойдет с моими сохраненными запросами, если я удалю плагин?**
О: Ничего критичного. Настройки плагина хранятся в текстовом поле `options` в формате YAML. Redmine безопасно игнорирует неизвестные ему ключи (такие как `hierarchy_enabled`). Запросы продолжат работать в стандартном плоском режиме.

**В: Почему задачи сгруппированы по родителю, но сортировка кажется странной?**
О: Убедитесь, что вы настроили сортировку в блоке **Сортировка подзадач**, а не только в основном блоке. Основной блок сортирует только корни.
