# Иерархия задач с сортировкой и связями (Redmine Hierarchy Sort)

Плагин для Redmine, обеспечивающий иерархическую сортировку задач с сохранением древовидной структуры и визуализацией связей между задачами.

## 📋 Описание

**Redmine Hierarchy Sort** расширяет стандартные возможности Redmine, позволяя:

- 🔹 **Сохранять иерархию задач** при любой пользовательской сортировке (по приоритету, дате, статусу и т.д.)
- 🔹 **Применять независимые фильтры** для корневых задач и их потомков
- 🔹 **Настраивать отдельную сортировку** для каждого уровня вложенности
- 🔹 **Сортировать и фильтровать задачи по полям их непосредственного родителя**
- 🔹 **Визуализировать связи** между задачами через удобные всплывающие окна
- 🔹 **Работать с межпроектными связями** — потомки могут находиться в других проектах

### Основные возможности

#### Иерархическая сортировка и пагинация
- Дочерние задачи всегда остаются внутри своих родительских задач.
- Сортировка применяется к "братьям" (задачам одного уровня).
- **Пагинация считается только по корневым задачам**: на странице отображается N корневых веток (например, 25), каждая со всеми своими потомками.
- Поддержка неограниченной глубины вложенности.

#### Расширенная фильтрация и сортировка (Новое в v2.x)
- **Фильтры по полям родителя**: В блоке фильтров доступна группа «Родительская задача», позволяющая отбирать задачи на основе атрибутов их непосредственного родителя (например, "Статус родителя = Открыт").
- **Сортировка по полям родителя**: В критерии сортировки добавлены виртуальные колонки с префиксом «Верх.: » (например, «Верх.: Приоритет», «Верх.: Пользовательское поле»), реализованные через эффективные коррелированные подзапросы.

#### Визуализация связей
- Иконка связей рядом с каждой задачей (если опция включена и связи есть).
- Всплывающее окно с группировкой по типам связей (блокирует, дублирует, связана с и т.д.).
- Отображение обоих направлений связей (входящие ←, исходящие →, двунаправленные ↔).
- Кликабельные номера связанных задач.

#### Кастомизация и безопасность
- При включении иерархии таблица задач получает CSS-класс `hierarchy-sort` для гибкой настройки стилей через пользовательский CSS.
- **Безопасное удаление**: Все настройки хранятся в поле `options` таблицы `queries` в формате YAML. При удалении плагина Redmine игнорирует неизвестные ключи (`hierarchy_enabled`, `child_filters` и т.д.), не нарушая работу сохраненных запросов. Миграции БД не требуются.


### Алгоритм работы `HierarchyBuilder`
1. **Анализ запроса**: Определение полей для фильтрации и сортировки.
2. **Загрузка корней**: SQL-запрос с фильтрами и сортировкой, выбор только `id` и `parent_id`.
3. **Определение относительных корней**: Удаление задач, чьи родители уже есть в выборке.
4. **Пагинация**: Применение `limit` и `offset` к массиву корней.
5. **Рекурсивная загрузка потомков**: Пошаговая загрузка (level-by-level) с применением `child_filters` и `child_sort_criteria`.
6. **Финальная загрузка**: Сборка дерева через DFS (поиск в глубину) и условная предзагрузка (conditional preloading) связей, затраченного времени и последних комментариев.

##  Установка

### Требования

- Redmine версии 5.0 или выше
- Ruby 2.7+
- База данных: MySQL, PostgreSQL или SQLite

### Установка из GitHub

1. Перейдите в директорию плагинов вашего Redmine:
   ```bash
   cd /path/to/redmine/plugins
   ```

2. Клонируйте репозиторий плагина:
   ```bash
   git clone https://github.com/selfauthor/redmine_hierarchy_sort.git
   ```

3. Перезапустите приложение Redmine:
   ```bash
   # Для Passenger
   touch /path/to/redmine/tmp/restart.txt
   
   # Для Puma/Unicorn
   sudo systemctl restart redmine
   ```

5. Очистите кэш Redmine (опционально, но рекомендуется):
   ```bash
   cd /path/to/redmine
   bundle exec rake tmp:cache:clear
   ```

### Проверка установки

После установки:
1. Откройте Redmine в браузере
2. Перейдите в раздел "Задачи" любого проекта
3. Нажмите "Новый запрос" или отредактируйте существующий
4. В блоке "Опции" должны появиться чекбоксы "Дерево подзадач" и "Показывать связи"

### Безопасность при удалении

Если плагин будет удален:
- Все настройки хранятся в поле `options` таблицы `queries` в формате YAML
- Redmine игнорирует неизвестные ключи (`hierarchy_enabled`, `child_filters` и т.д.)
- Существующие запросы продолжают работать без ошибок
- Никаких миграций БД не требуется

## 🐛 Известные ограничения
1. **Производительность**: При отсутствии фильтров и огромном количестве задач (10000+) первая загрузка может занять 1-2 секунды из-за рекурсивной природы выборки.
2. **Экспорт**: При экспорте в CSV/PDF иерархическая структура не сохраняется — задачи экспортируются плоским списком (стандартное поведение Redmine).
3. **Группировка**: Режим группировки (`group_by`) не совместим с иерархической сортировкой.
